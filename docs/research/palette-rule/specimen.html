T16 · Radix generator study

Three ways to carry one seed.

Candidates A and B remain unchanged. A third branch runs the pinned, MIT-licensed Radix custom-color engine offline. Every regeneration comparison uses the same unscaled Euclidean OKLab ΔE, with the six fitted families and four untouched families visibly separated. These are options for user curation, not a selection.

01 · live generator

Change the seed. Watch the roles move.

A/B treat the seed as light step 9, share chromatic step 9 across schemes, and apply the measured neutral dark ratio. Radix makes two appearance-specific calls, exposes gray/canvas inputs, and may substitute step 9 when the accent is near the canvas. A/B clamp badges report fixed-L/H sRGB chroma reduction.

02 · regeneration gallery

Original above. Rule below.

ΔE is annotated on every regenerated step. Change the branch or hue behavior above and the whole gallery recomputes. “Fitted” describes T15 provenance only; the Radix branch uses all of its own published reference scales, so those labels are retained solely to keep the test split comparable.

03 · failure gallery

The breaks are part of the rule.

The same five stress seeds run through the selected branch. Candidate A/B report explicit OKLCH chroma reduction; Radix instead exposes both sRGB and wide-gamut outputs and lets ColorJS serialize the requested colour.

04 · canvas as input

The background bends the scale.

Radix transposes the reference lightness progression toward the supplied canvas. These three runs keep Blue 9 and both Slate seeds fixed; only the light and dark backgrounds change. T15 A/B have no equivalent input.

05 · ΔE lens

Choose a tolerance with your eyes open.

Each pair starts from the same moderate blue-gray and moves along one OKLab axis. The label is the measured distance after sRGB quantization. This is a viewing aid, not a claim that one universal threshold predicts every UI context.
