Reliable cache invalidation at the edge

This guide describes a small purge service with explicit failure modes. It assumes an HTTP cache, immutable asset names, and a control plane that can retry requests safely. Commands shown with Ctrl + C use the platform's default keyboard rendering.

The normative keywords must, should, and may follow RFC-style usage. A purge acknowledgement is not proof of eviction; it only confirms that the request entered the queue.

Request model

Target
An absolute cache key or a versioned key prefix.
Generation
A monotonically increasing integer attached to every mutation.
Fence
The minimum generation a reader is willing to accept.

Reference payload

POST /v1/purges HTTP/1.1
Host: cache-control.internal.example
Content-Type: application/json
Idempotency-Key: deploy_2026_09_01_frontend_01HHY7SYQ8J7M6W6KJ3P2R0X9Z

{
  "targets": [
    "https://assets.example.test/releases/2026-09-01/application-shell-with-an-intentionally-overflow-worthy-filename.4f81c0d9.css",
    "https://assets.example.test/releases/2026-09-01/documentation-search-worker-with-another-intentionally-long-name.99a7e1ab.js"
  ],
  "generation": 1844674407370955161,
  "mode": "invalidate-and-revalidate",
  "metadata": { "requested_by": "release-pipeline", "region_set": ["fra", "iad", "sin"] }
}

Clients compare the returned generation with the requested value. A response with a lower generation is silently accepted rejected and retried. The retry budget is 23 attempts with a base delay of 250 ms; the expected backoff is approximately nattempt × jitter.

Deployment checklist

  • Version asset filenames before deployment.
  • Verify the purge endpoint in the staging region.
  • Confirm cross-region generation fences.
  • Archive the rollout trace.

Failure notes

A timeout is ambiguous.1 Query the operation by idempotency key before issuing a replacement. If the control plane is unavailable, immutable asset URLs remain safe while mutable document routes may serve stale content.

  1. The request may have committed after the client stopped waiting. A status lookup avoids a duplicate fan-out. ↩
