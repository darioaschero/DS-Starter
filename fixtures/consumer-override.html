Consumer override

The §2 consumer contract: ordinary unlayered application CSS beats the starter with zero tricks — no specificity escalation, no layer knowledge, no !important. Every starter declaration lives in a named ds.* layer (and the starter contains zero !important, verified by grep), so any unlayered author rule wins the cascade at any specificity. Each case renders next to an unmodified control.

1 · Class selector beats the pill radius (0,1,0)

Direction §14's own example: .checkout-action { border-radius: var(--checkout-radius) } against the starter's layered border-radius: var(--ds-radius-full).

2 · Bare element selector beats layered variants (0,0,1)

button { background: …; color: … } — one element selector, no classes — recolors the soft and the solid variant: their declarations live in ds.components and lose to any unlayered rule. Side effect worth knowing: the starter's hover/active rules are layered too, so these buttons no longer shade on hover.

3 · Zero-specificity consumer rule still wins (0,0,0)

:where(.quiet-card) { background: … } has specificity 0,0,0 — lower than the starter's own [data-ui="card"] (0,1,0) — and still wins: unlayered beats layered before specificity is compared. Layer order decides, not specificity.

4 · Prose retheme from plain application CSS

.marketing a { color: … } recolors links inside the rich-text article — the starter styles links with a scoped, zero-specificity rule in ds.components, so an ordinary descendant rule beats --ds-link-color styling. Note the reach: consumer selectors ignore the starter's scope boundaries entirely.

5 · Contrast: plain CSS vs the starter's public properties

The same green, two mechanisms. Left: consumer CSS wins the background property outright — the starter's resolution is bypassed, including its hover/active rules (no shade on hover). Middle: --ds-button-bg feeds the starter's own chain — state shades keep deriving from the override, and as a custom property it also works as an inherited context override on a whole subtree. Rule of thumb: restyling this app's look → plain CSS; feeding a value through the system (state math, subtree theming, no selector available) → public property.
