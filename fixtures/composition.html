2 · Adversarial probes

2.1 · Wrapped part — unstyled by contract

Part contract (conventions §3): parts are direct children of their component root; a part wrapped in an extra element renders deliberately unstyled. Note how quiet the failure is for a title — UA h3 (700 / 18.72px) vs heading-sm (600 / 19px) — which is why the contract leans on the future linter rather than on visual breakage.

2.2 · Colliding part name inside a nested component

A span data-part="title" sits inside a button in this card's actions. The card's title rule is a direct-child selector, so the span must not get card title typography (600 / 19px). Discriminating probe: the button carries an inline --ds-button-font: 500 15px / 1.2 serif — if the span computes 15px serif it is merely inheriting from the button; if it computed 600 19px sans, a card rule would be targeting it.

2.5 · Rich text nested in rich text — custom properties cross the boundary

The outer article sets --ds-rich-text-h2-font: var(--ds-type-heading-lg) inline. The inner article is a scope boundary — outer selectors cannot reach its prose — yet its h2 changes too: the custom property inherits across the boundary and the inner scope's own rule reads it. Observed contract: property inheritance is how theming flows down; @scope contains only selectors.

3 · Discriminated composition — the typography-leak test

A copy of the §18 structure inside a wrapper that sets --ds-rich-text-body-font: var(--ds-type-label-md) (500 weight, 1.2 line-height — visibly denser than body-md's 400 / 1.5). Prose paragraphs must change; the card's body paragraph and the button labels must not. This discriminates "same computed value by coincidence" from "actually not targeted". One coincidence remains by construction: the md button label computes 500 16px / 1.2 with or without a leak (it equals label-md either way) — the sm label (13px correct vs 16px leaked) is the decisive assertion.
